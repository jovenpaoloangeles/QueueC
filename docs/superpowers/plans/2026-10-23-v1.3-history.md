# v1.3 History & Corrections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make history first-class — session history browser, session detail (live + ended), player career page, attendance tracking, corrections (scores/shuttles/rating/players/match-delete/attendance) with derived-stat recompute, and CSV/JSON export.

**Architecture:** All v1.3 data already persists (`sessions`, `matches`, `queue_entries`, `players`) — this is read paths plus a corrections write path. History/career/export queries read `matches` directly (the match log is the source of truth); corrections run in one transaction that recomputes the denormalized `queue_entries.games_played` / `total_seconds_played` / `last_played_at` from ended matches. Client gets hand-rolled hash routing; history pages fetch JSON endpoints and treat SSE broadcasts as refetch signals (the 1-second live broadcast payload does not grow).

**Tech Stack:** Hono + bun:sqlite (server), React SPA + Tailwind (client), Playwright e2e, bun test (unit + API-level server tests). No new runtime dependencies.

**Spec:** docs/superpowers/specs/2026-10-23-v1.3-history-design.md (read it first — it rules on data preservation, slot mapping, attendance delegation, and the fetch/SSE split).

## Global Constraints

- Never target :3001 (live container). Server tests boot a throwaway server on :3991 (`bun run --cwd tests test:server`, temp DB, `PLAYERS_PATH=tests/fixtures/players.json`).
- No new runtime dependencies (no router package; hand-rolled hash routing).
- Every correction/attendance write: single `db.transaction`, then `broadcast()` (import from `./sse.js`).
- Ended match = `state = 'active' AND ended_at IS NOT NULL`. Slated rows (`state='slated'`) are never corrected or exported as games.
- Scores 0–99 integers, rating 1–5, shuttles ≥ 0 integers — same validation as `PATCH /matches/:id/end` (server/routes/matches.js:122-137).
- `queue_entries.virt_offset` column exists (db.js:318) — check-ins must inherit it on live sessions.
- Test policy (CLAUDE.md): implementer runs unit + server tests for logic changes + only the specs its change touches (`bun run --cwd tests test:touched <rev>`); server-state assertions are API-level, browser specs assert only UI re-render. Known pre-existing e2e failures on master: 21.2/21.5 (not ours to fix here).
- New server test files must be registered in `tests/scripts/run-server-tests.js` (list at ~line 46).

## Review Focus

1. **Recompute correctness** — after swapping a player between two historical matches, both entries' `games_played` / `total_seconds_played` / `last_played_at` equal a fresh aggregate over ended matches. Pinned by Task 2's test (corrections.test.js recompute assertions).
2. **Correction while players are queued** — moving a currently-`playing` player INTO a corrected match must 409; an old player leaving the corrected match keeps their live `status` untouched (only counts recompute). Pinned by Task 2's tests.
3. **Attendance delete refusal** — deleting a queue entry that appears in ANY match 409s (ended or live), message names the reason. Pinned by Task 3's test.
4. **Singles vs doubles shape** — `players` array length must equal the match's format (2 singles / 4 doubles); wrong length 400s. Pinned by Task 2's test.
5. **Export shape stability** — JSON export is byte-identical in structure to the page payloads (same endpoint helper feeds both); CSV has all sections. Pinned by Task 6's test.

### Task 2: Corrections endpoint — `PATCH /api/matches/:id/correct`

**Files:**

**Interfaces:**
- Produces: `recomputeEntries(entryIds: number[])` — exported from `server/routes/matches.js`; per entry, recomputes `games_played` = COUNT of ended active matches containing it, `total_seconds_played` = SUM(`ended_at - started_at`) over those, `last_played_at` = MAX(`ended_at`) (null when none); does NOT touch `status`, `sort_order`, `virt_offset`, or `checked_in_at`.
- Produces: `PATCH /api/matches/:id/correct` — ended matches only (404 otherwise); body all-optional but ≥1 required: `team1_score`, `team2_score`, `new_shuttles`, `used_shuttles`, `rating`, `players` (in-order slot mapping: doubles `[team1_p1, team1_p2, team2_p1, team2_p2]`, singles `[team1_p1, team2_p1]`); success returns `{ match }` after recompute + `broadcast()`.

  4. `players` length 4 on a singles match (and length 2 on a doubles match) → 400;

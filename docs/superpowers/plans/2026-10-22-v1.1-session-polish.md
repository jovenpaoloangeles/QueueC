# v1.1 Session Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship all 8 ROADMAP.md v1.1 items: pause session, undo last action, bulk check-in, idle-court nudge, keyboard shortcuts, late-game draft restore, named teams in score & UI, alphabetical-vs-arrival check-in toggle.

**Architecture:** Server is the truth (SQLite + Hono + 1 Hz SSE broadcast of the whole state); client is a thin SSE mirror. Time math (waits, match durations, court rental) all derive from stored timestamps, so **pause is implemented as timestamp-shifting on resume**, not as a formula change anywhere. Undo is a single-level client-side registry attached to the existing Toast. Drafts stay client-local and gain sessionStorage persistence keyed by session id.

**Tech Stack:** Bun + Hono + bun:sqlite (server), React 18 + Vite + Tailwind 4 (client), Playwright (e2e), node:assert scripts (server tests).

**Spec:** ROADMAP.md §v1.1 (the 8 bullet items are the spec).

## Global Constraints

- No new npm/bun dependencies.
- Server tests are assert-scripts in `server/routes/*.test.js` run via `bun run --cwd tests test:server` (boots a throwaway server on :3991 with a temp DB — **never target :3001**, that's the live container).
- E2E specs in `tests/e2e/NN-name.spec.js`; single-spec run: `cd tests && bunx playwright test --config=playwright.config.js e2e/<spec>`. API-seeded setup via `fullSetup` from `tests/helpers.js`.
- Every new UI element gets a `data-testid`.
- All live state arrives via the SSE `state` event (`server/routes/sse.js` `currentState()`); the client never invents server state.
- Biome formatting: run `bunx biome check --write <changed files>` before committing.
- Commits: one per task, conventional (`feat:`, `fix:`), imperative.

## Review Focus

1. **Match ends while session is paused** — a stale client can still PATCH `/matches/:id/end`; duration math would swallow the pause. Expected: the end route refuses with 409 while paused. Pinned by Task 1 test.
2. **Refresh during pause** — `paused_at` is persisted, so a reload must land frozen, not resume timers. Pinned by Task 1 e2e.
3. **Undo after the target vanished** (match ended on another client between start and Undo click) — expected: graceful info toast, no crash. Pinned by Task 2 test.
4. **Draft restore across session end** — stored drafts reference old session's entry ids; the existing stale-draft pruning must null them, not crash. Pinned by Task 6 e2e.
5. **Bulk check-in with a duplicate in the batch** (someone checked in from another device mid-selection) — server 409s that one; expected: the rest check in, toast reports partial. Component-internal, no isolated harness — pinned by review, not a test.

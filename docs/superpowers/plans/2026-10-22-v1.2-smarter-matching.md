# v1.2 Smarter Matching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.2 — wave-crossover objective in the match engine + tuning, two rotation-rule session settings, and partial-lineup lock in Smart Match.

**Architecture:** All engine work lands in `server/logic/smartQueue.js` (`planBatch`, the two-stage ε-lexicographic engine): a new γ-decayed shared-round overlap matrix feeding a first-position Stage A band (`epsOverlap`), a `restGames` cfg knob in the unary filter, and a `locked` param that constrains the quartet mask. Rotation settings are session columns (v1.1 `checkin_order` pattern: migration + POST validation + SetupScreen controls). Partial-lineup lock is a `locked` array on the slate-only dry-run, honored only there. Client work is `SetupScreen.jsx` (two selects) and the On Deck builder pour (send locked ids, map results back by slot, disable on full builder).

**Tech Stack:** Bun + Hono + bun:sqlite (server), React 18 + Vite + Tailwind 4 (client), Playwright (e2e), node:assert unit tests, existing DES harness in `tests/sim/` for tuning.

**Spec:** `docs/superpowers/specs/2026-10-22-v1.2-smarter-matching-design.md` (read both; spec wins on conflicts).

## Global Constraints

- Defaults are behavior-identical to today: `epsOverlap` ships at its tuned value but round-1 behavior is unchanged (all overlaps 0), `max_consecutive` default 2, `rest_games` default 0 (off).
- Graceful relax stays exactly as shipped: it may override consecutive and rest-games limits only when fewer than 4 players are eligible, and still prefers lowest streaks.
- No new npm dependencies. No engine rewrite — additions to the existing cascade only.
- Locked is honored only with `slate_only: true`; anything else → 400.
- Test policy (CLAUDE.md): engine/planner rules = `tests/unit/*.test.js` (node:assert, registered in `tests/package.json` `test:unit`); route behavior = `bun run --cwd tests test:server`; browser specs only assert UI re-render; never target :3001.
- Commands: unit `bun tests/unit/smartqueue.test.js` · server suite `bun run --cwd tests test:server` · single e2e `cd tests && bunx playwright test --config=playwright.config.js e2e/<spec>` · sim `bun tests/sim/benchmark-sim.mjs` · sweep `bun tests/sim/epsilon-sweep.mjs`.

## Review Focus

1. **Band-first cascade must never empty the survivor set on small pools** — with 4–7 waiting, the overlap band keeps quartets relative to the minimum, so some quartet must always survive; a plan that returns zero matches for a feasible pool is the failure. (Pinned by Task 1's probe test + Task 6's locked-feasible test.)
2. **`rest_games` vs graceful relax** — a session with `rest_games: 1` and exactly 4 players who all just played must still field a game (relax overrides rest), never a hard "nothing to add". (Task 4.)
3. **`locked` validation edges** — locked id not waiting / duplicate / length > 3 / missing `slate_only` each → 400 with a message; a locked player outside the top-K window must still be planned around. (Task 6.)
4. **Pre-migration sessions** — a session row created before the columns exist (defaults applied by migration) must plan identically to today. (Task 4's server test creates a session omitting the fields and asserts the default plan path.)
5. **Builder pour must preserve slot identity** — locked picks stay in the slots the QM chose even when the planner returns them in different positions. (Task 7's e2e.)

```js
// U5.1 — wave crossover: 16 players / 2 courts must mix the first-8 and
// last-8 waves instead of alternating them forever (0% mixed = regression).
import { planBatch } from "../../server/logic/smartQueue.js";
const T0 = 1_800_000_000, GAME = 720;
const players = Array.from({ length: 16 }, (_, i) => ({
  id: i + 1, status: "waiting", skill_level: "intermediate",
  checked_in_at: T0, last_played_at: null, total_seconds_played: 0, games_played: 0,
}));
const history = [];
const wave = new Map();
let mixed = 0, total = 0;
for (let r = 0; r < 12; r++) {
  const now = T0 + r * GAME;
  const plan = planBatch({ waiting: players, history, courtCount: 2, now });
  for (const m of plan.matches) {
    const q = [...m.team1, ...m.team2];
    if (wave.size >= 16) {
      const sets = new Set(q.map((id) => wave.get(id)));
      total++;
      if (sets.size === 2) mixed++;
    }
    for (const id of q) if (!wave.has(id)) wave.set(id, wave.size < 8 ? "A" : "B");
    history.push({ team1: [q[0], q[1]], team2: [q[2], q[3]], started_at: now, ended_at: now + GAME });
    for (const id of q) {
      const p = players.find((x) => x.id === id);
      p.games_played++;
      p.last_played_at = now + GAME;
    }
  }
}
assert.ok(total >= 16, `expected a full session, got ${total} post-wave quartets`);
assert.ok(mixed >= 4, `wave crossover: expected ≥4 mixed quartets of ${total}, got ${mixed}`);
```
